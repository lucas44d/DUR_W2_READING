# DUR_W2_READING — Refractometer Acquisition & RTD Analysis

C++/Qt project that reads live measurements from a Schmidt+Haensch DUR-W2
refractometer over a serial (RS-232) connection, logs them to CSV, streams
them in real time to Teleplot, and computes/visualizes a Residence Time
Distribution (RTD) analysis (concentration, F(t), residence time) in a Qt
viewer.

## What this project does

1. Opens a COM port and reads raw ASCII frames from the refractometer
   (9600 8N1).
2. Parses each frame into: measurement number, refractive index,
   temperature, brix, device date/time.
3. Converts refractive index to **concentration** using a linear
   calibration, then computes the cumulative RTD function **F(t)**.
4. Timestamps every measurement with PC-side time (millisecond precision
   — the device itself only reports time to the minute).
5. Streams every measurement live to **Teleplot** (VS Code extension) for
   real-time monitoring, regardless of whether recording is on.
6. Logs measurements to a **CSV** file, but only while recording is
   active (toggled with a keypress).
7. A separate **Qt viewer** app tails the CSV file and displays:
   - refractive index vs. time
   - concentration and F(t) vs. time (dual Y-axis)
   - a live-updating **residence time** estimate

| Tool | Version used | Notes |

| Qt | 6.11.2 | installed at `C:\Qt\6.11.2\mingw_64` |

Two different compilers are used on purpose: the acquisition program
(`src/`) builds with your general-purpose MinGW (winlibs), while the Qt
viewer (`viewer/`) **must** build with the MinGW compiler that shipped
with your Qt installation, to avoid ABI mismatches with the Qt libraries.

## One-time setup

1. **Find the refractometer's COM port**: Windows Device Manager →
   Ports (COM & LPT). Note the number (e.g. `COM5`) — it can change if
   you plug the device into a different USB port.
2. **Install the Teleplot extension** in VS Code (search "Teleplot",
   publisher `alexnesnes`). It listens on UDP port `47269` by default —
   nothing to configure.
3. **Verify Qt's MinGW kit path**: confirm `C:\Qt\Tools\mingw1310_64\bin\g++.exe`
   exists (folder name encodes the GCC version, e.g. `mingw1310_64` =
   GCC 13.1.0). If your install differs, adjust the paths below and in
   `viewer/CMakeLists.txt`.
4. **First-time Windows security note**: if `main.exe` refuses to launch
   with *"Une stratégie de contrôle d'application a bloqué ce fichier"*,
   Windows **Smart App Control** is blocking unsigned local builds.
   Disable it under `Windows Security → App & browser control` (personal
   PCs only — on a managed/university PC, this is an IT-controlled policy
   and can't be changed locally).

## Building & running the acquisition program

```powershell
cd C:\Dev\DUR_W2_READING
```

**Option A — VS Code (recommended):** press `F5`, select the
**"Debug refractometer (GDB)"** launch config, and enter the COM port
when prompted.

**Option B — command line:**
```powershell
g++ -g -std=c++17 -Wall -Wextra `
  src\main.cpp src\serial.cpp src\protocol.cpp src\csv.cpp `
  -lws2_32 `
  -o build\main.exe

.\build\main.exe COM5
```
(`-lws2_32` is required — the program uses Winsock for Teleplot.)

**Once running:**
- Raw frames, parsed measurements, and computed concentration/F(t) print
  continuously to the console.
- Data streams to Teleplot **immediately and continuously**, whether or
  not you're recording.
- Press **SPACE** or **ENTER** to toggle CSV recording on/off. A new CSV
  file is created the moment you press it (named
  `data/refractometer_YYYYMMDD_HHMMSS.csv`); pressing again pauses
  recording (the console prints `[DEBUT ENREGISTREMENT CONTINU]` /
  `[PAUSE ENREGISTREMENT]`).
- `Ctrl+C` stops everything cleanly (closes the serial port, flushes and
  closes the CSV, cleans up the Teleplot socket).

### Watching Teleplot

Open the Teleplot panel in VS Code (Command Palette → "Teleplot: Open" or
click its icon). As soon as the acquisition program is running, you
should see live traces for `RefractiveIndex`, `Brix`, `Temperature`,
`Concentration`, and `F_t` — no extra setup needed.

### CSV format

```
timestamp_pc;measurement_number;refractive_index;temperature;brix;concentration;f_t;device_date;device_time
2026-08-27 14:57:48.548;13;1.33273;23.74;0.08;0.152;0.0380;08/23/05;04:39
```

- `timestamp_pc` — PC reception time, millisecond precision (used as the
  canonical timestamp; the device's own `device_date`/`device_time`
  columns are kept for traceability but only have minute resolution).
- `concentration` / `f_t` — computed from the refractive index using the
  calibration in `main.cpp` (see below), so the viewer doesn't need to
  duplicate those constants.
- Delimiter is `;` (not `,`) for reliable direct opening in French-locale
  Excel, where `,` is the decimal separator.

## Building & running the Qt viewer

```powershell
cd C:\Dev\DUR_W2_READING\viewer

# First time only (or after deleting build/):
mkdir build
cd build
cmake .. -G "MinGW Makefiles" `
  -DCMAKE_C_COMPILER="C:\Qt\Tools\mingw1310_64\bin\gcc.exe" `
  -DCMAKE_CXX_COMPILER="C:\Qt\Tools\mingw1310_64\bin\g++.exe" `
  -DCMAKE_PREFIX_PATH="C:\Qt\6.11.2\mingw_64"

# Every time after that, from viewer\build:
cmake --build .
```

**Make the exe runnable without touching PATH every time** (run once
after each build, from `viewer\build`):
```powershell
C:\Qt\6.11.2\mingw_64\bin\windeployqt.exe .\RefractometerViewer.exe
```
This copies the required Qt DLLs next to the executable so you can just
double-click it afterward.

**Running:**
```powershell
.\RefractometerViewer.exe ..\..\data\refractometer_20260827_145700.csv
```
Or run it with no argument to get a file picker. Or, in VS Code, select
the **"Run Viewer (Qt)"** launch config and press `F5` (it injects the
right `PATH` automatically, no need for `windeployqt` in that case).

The viewer polls the CSV file every 500 ms, so you can start it while the
acquisition program is still running and watch the charts update live.

### What the viewer shows

- **Top chart** — refractive index vs. time, with markers on each point
  (the real measurement interval is ~15 s, so a plain line would
  misleadingly suggest a continuous signal) and running min/max/mean
  stats below it.
- **Bottom chart** — concentration (left axis, %) and F(t) (right axis,
  0–1) vs. time.
- **Residence time**, updated live below the bottom chart:
  `τ = Σ (1 − F(t)) · Δt`, where `Δt` is the **actual** elapsed time
  between consecutive PC timestamps (not an assumed fixed step — the
  device's real measurement cycle varies slightly, ~15.17–15.32 s). A
  note appears while `F(t) < 0.95`, since τ is only a complete estimate
  once the concentration has stabilized near its final value.
- An **"Export as image..."** button saves the current state of both
  charts + stats as a PNG.

## Calibration constants (in `src/main.cpp`)

```cpp
constexpr double kCalibA = 0.00146067;
constexpr double kCalibB = 1.33251321;
// concentration = (refractiveIndex - kCalibB) / kCalibA

constexpr double kConcentrationInit  = 0.0;
constexpr double kConcentrationFinal = 4.0;
// F(t) = (concentration - kConcentrationInit) / (kConcentrationFinal - kConcentrationInit), clamped to [0,1]
```
Update these if you recalibrate the refractometer or change the tracer
solution's concentration range — they're defined in exactly one place and
used consistently for the console output, the CSV, and the Teleplot
stream.

## Known quirks

- **Measurement cycle is ~15 s, not 1 Hz.** The original LabVIEW config
  (9600 8N1) describes the *serial link* parameters, not the device's
  actual measurement rate. Confirmed with the manufacturer/technician:
  the refractometer needs that time to thermally stabilize each reading.
  This is normal behavior, not a bug in this program.
- **Device date/time have only minute resolution** (no seconds) — this
  is why `timestamp_pc` (not the device's own timestamp) is used as the
  canonical time reference throughout.
- **Frames with `*` characters** (e.g. `*33****`) mean the device
  couldn't produce a valid reading for that cycle (out-of-range sample,
  poor optical contact, etc.). The parser correctly rejects these lines
  (`[ERREUR PARSING]` in the console) rather than guessing a value —
  they are never written to the CSV.
- If you add a new `.cpp` file to either `src/` or `viewer/`, remember to
  add it to `.vscode/tasks.json` (for `src/`) — a missing file there
  produces `undefined reference` link errors that are easy to
  mis-diagnose as a code bug.
